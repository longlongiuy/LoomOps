# 织序 · LoomOps

织序是一个可运行的多 Agent 编排、调度与验证原型。预置任务为经营订单质量审计，使用 8 条样例订单演示重复订单、负金额和区域缺失的检测与处置。

## 启动

需要 Node.js 22 或更高版本。应用不依赖第三方 npm 包。在解压目录运行：

```powershell
node server.mjs
```

浏览器打开 `http://127.0.0.1:4173`。如果只需要离线演示，可以直接在浏览器打开 `dist/index.html`。

## 复现审计闭环

1. 进入工作流编排页，点击「运行工作流」。默认离线样例会让分析 Agent 在首轮遗漏一条证据引用。
2. 验证门比较两个 Agent 的汇总字段、异常 ID 和知识规则引用，记录失败快照，只回退失败 Agent 任务及其下游。调度器会降低上一执行者的得分，样例将失败分支重新分配给审计顾问。
3. 通过后，报告列出 6 笔有效订单、有效收入 ¥73,250.00 和 3 项异常。运行历史可以导出快照，也能恢复当时的工作流、知识与 Agent 版本来重跑。
4. 在「运行配置」将重试上限设为 0，或开启人工复核，可分别验证异常回退与强制审核。审核员填写意见并选择批准或拒绝，报告保留人工决定。
5. 在「运行记录」选择「调度对比」，即可在同一份样例数据与固定节点等待时间下，比较串行和并行调度各三次的中位耗时。该对比隔离了模型网络延迟，输出的是模拟结果。

## DeepSeek 实时模式

打开「模型设置」，选择「DeepSeek 实时推理」，输入自己的 DeepSeek API Key，点击「测试连接」再保存。默认模型 `deepseek-flash`，也支持 `deepseek-v4-pro`。应用通过同源代理调用 `https://api.deepseek.com/chat/completions` 的 JSON 输出接口。Key 仅保留在当前标签页内存，刷新后需要重新输入。也可以在启动前通过服务端环境变量 `DEEPSEEK_API_KEY` 提供密钥。

实时模式将任务描述、聚合统计、异常明细、匹配规则和修正反馈发给 DeepSeek。输入 CSV 和运行历史保存在当前浏览器。若处理真实订单，应先将订单号与可识别的字段脱敏。离线模式使用确定性模拟，不调用模型，也不消耗 API 额度。

## 编排与实现

| 模块 | 实现 |
| --- | --- |
| Agent 团队 | 可注册、启停、编辑能力和并发容量。修改时递增版本。支持按 Agent 配置提示词、工具上下文和反馈记忆。 |
| DAG | 点击节点可配置依赖、优先级和位置。JSON 定义支持条件分支与最多三层的子工作流嵌套。保存时检查依赖和循环。 |
| 调度 | 用节点优先级加 `10 × 最长下游路径长度` 排序就绪任务。Agent 评分为 `适配分 - 60 × 当前负载比例 - 上一执行者惩罚 35`。 |
| 检索与工具 | CSV 统计、异常规则、知识库关键词检索和证据 ID 精确匹配，均由本地代码执行。 |
| 验证 | 重新核对有效收入、订单数、异常集合及规则引用。人工覆盖保留原验证结论。校验可以检查建议是否填写，建议的业务语义仍需要人工判断。 |
| 可追溯性 | 运行事件、分配得分、Agent 版本、中间输出和修订前快照均可导出。历史记录使用当前浏览器的本地存储。 |

`dist/engine.js` 是调度与校验核心，`dist/app.js` 是交互界面，`proxy.mjs` 实现 DeepSeek 适配和路由。`server.mjs` 提供本机访问服务，`build.mjs` 将页面资源打包成 Cloudflare Worker 模块 `dist/server/index.js`。

```powershell
node --test test.cjs
node build.mjs
```

当前原型以订单审计为适配场景。知识库使用基于关键词和证据 ID 的检索。工具接入为平台内置调用，工作流执行与存储以当前浏览器为边界。
